# 司机端前端页面规划

## 一、司机端现有接口分析

根据 `driver-srv/internal/server/driverserver.go`，现有 **19 个 RPC 接口**，分为 4 大模块：

### 1.1 认证模块（4 个接口）

| 接口名 | 功能 | 请求参数 | 返回数据 |
|--------|------|---------|---------|
| `SendSms` | 发送短信验证码 | phone（手机号） | success |
| `DriverRegister` | 司机注册 | phone, code, nickname | driverId |
| `DriverLogin` | 司机登录 | phone, code | driverId, token |
| `OutLogin` | 退出登录 | 无 | success |

### 1.2 司机信息模块（4 个接口）

| 接口名 | 功能 | 请求参数 | 返回数据 |
|--------|------|---------|---------|
| `GetDriverInfo` | 获取司机信息 | driverID | driverID, phone, realName, authType, auditStatus, licenseNo, licenseExpire, driveYears |
| `UpdateDriverInfo` | 更新司机信息 | driverID, nickname, avatarURL | success |
| `SubmitDriverCert` | 提交认证资料 | driverId, realName, picURL, licenseNo, licenseExpire, driveYears, authType | success |
| `StatusDriverCert` | 查询认证状态 | driverId | authType, auditStatus, reason, licenseNo, realName |

### 1.3 司机订单模块（7 个接口）

| 接口名 | 功能 | 请求参数 | 返回数据 |
|--------|------|---------|---------|
| `DriverOrderList` | 当前进行中订单 | driverId | 订单完整信息（起终点、乘客、状态、预估到达时间、价格等） |
| `DriverOrderHistory` | 历史订单列表（分页+筛选） | size, page, status, driverId, search_keyword, start_date, end_date, min_income, max_income, pay_status | 订单列表+总数（订单号、车型、状态、起终点、金额、收入、时间等） |
| `DriverOrderDetail` | 订单详情 | driverId, order_id | 完整订单详情（含乘客信息、收入明细、支付信息、投诉状态、乘客标签等） |
| `AcceptOrder` | 接受订单 | driver_id, order_id, order_distance, driver_current_location, anti_fraud_token | success, order_lock_time |
| `ArrivePassengerLocation` | 到达乘客位置 | driver_id, order_id, driver_lng, driver_lat, arrival_accuracy, arrival_photo | success |
| `StartTrip` | 开始行程 | driver_id, order_id, pickup_photo, start_odometer, passenger_confirm_code | success |
| `CancelOrder` | 取消订单 | driver_id, order_id, reason, evidence_photo | success, cancel_fee, cancel_responsibility, appeal_support |

### 1.4 司机状态模块（4 个接口）

| 接口名 | 功能 | 请求参数 | 返回数据 |
|--------|------|---------|---------|
| `DriverOnline` | 司机上线 | driver_id, driver_location, car_status, online_type | success, rest_reminder |
| `DriverOffline` | 司机下线 | driver_id, driver_location, car_status | success, rest_reminder |
| `StartAcceptOrder` | 开始接单 | driver_id | success |
| `StopAcceptOrder` | 停止接单 | driver_id | success |

## 二、可实现的页面及功能

基于以上接口，司机端 App 需要实现 **7 个页面**，采用**移动端手机风格**（参照 user-web 的样式体系）：

### 2.1 登录/注册页 (`login.html`)
**对应接口**: `SendSms`、`DriverLogin`、`DriverRegister`

| 功能点 | 说明 |
|--------|------|
| 手机号输入 | 11 位手机号输入框 |
| 短信验证码 | 点击发送验证码按钮 → 调用 `SendSms` |
| 登录按钮 | 验证手机号 + 验证码 → 调用 `DriverLogin`，成功后跳转首页 |
| 注册按钮 | 新用户输入昵称后 → 调用 `DriverRegister`，成功后跳转首页 |
| Token 存储 | 登录/注册成功后存储 token 到 localStorage |

### 2.2 司机首页/工作台 (`index.html`)
**对应接口**: `DriverOnline`、`DriverOffline`、`StartAcceptOrder`、`StopAcceptOrder`、`DriverOrderList`、`GetDriverInfo`

| 功能点 | 说明 |
|--------|------|
| 顶部状态栏 | 显示司机昵称、认证状态 |
| 上线/下线按钮 | 切换在线状态 → 调用 `DriverOnline` / `DriverOffline` |
| 接单开关 | 开始接单/停止接单 → 调用 `StartAcceptOrder` / `StopAcceptOrder` |
| 当前进行中订单卡片 | 调用 `DriverOrderList` 获取当前订单，显示起终点、乘客信息、订单状态 |
| 今日收入概览 | 展示预估今日收入（可从订单列表汇总） |
| 休息提醒 | 显示后端返回的 rest_reminder |
| 底部导航栏 | 首页、订单、消息、我的 |

### 2.3 订单详情页 (`order-detail.html`)
**对应接口**: `DriverOrderDetail`、`AcceptOrder`、`ArrivePassengerLocation`、`StartTrip`、`CancelOrder`

| 功能点 | 说明 |
|--------|------|
| 行程信息展示 | 出发地→目的地路线、距离、预估价格 |
| 乘客信息 | 姓名（脱敏）、电话、头像、备注、乘客标签 |
| 操作按钮 | 根据订单状态显示不同按钮： |
|  | - 待接单：接受订单 `AcceptOrder` |
|  | - 已接单：到达乘客位置 `ArrivePassengerLocation` |
|  | - 已到达：开始行程 `StartTrip` |
|  | - 进行中：显示行程进度 |
| 收入明细 | 总费用、平台费、实际收入 |
| 取消订单 | `CancelOrder` 含原因选择和证据照片 |
| 支付信息 | 支付状态、支付方式、支付时间 |

### 2.4 历史订单页 (`order-history.html`)
**对应接口**: `DriverOrderHistory`

| 功能点 | 说明 |
|--------|------|
| 订单列表 | 分页展示历史订单 |
| 搜索筛选 | 关键词搜索、日期范围、订单状态筛选、收入范围筛选、支付状态筛选 |
| 订单卡片 | 显示订单号、车型、起终点、金额、收入、服务分、时间 |
| 点击查看详情 | 跳转订单详情页 |

### 2.5 个人信息页 (`profile.html`)
**对应接口**: `GetDriverInfo`、`UpdateDriverInfo`、`OutLogin`

| 功能点 | 说明 |
|--------|------|
| 头像展示 | 显示司机头像 |
| 昵称编辑 | 修改昵称 → `UpdateDriverInfo` |
| 手机号展示 | 显示注册手机号（只读） |
| 认证状态展示 | 显示认证类型、审核状态 |
| 退出登录 | `OutLogin`，清除 token 返回登录页 |

### 2.6 认证中心 (`certification.html`)
**对应接口**: `SubmitDriverCert`、`StatusDriverCert`

| 功能点 | 说明 |
|--------|------|
| 认证状态展示 | 审核中/已通过/已驳回，显示驳回原因 |
| 认证表单 | 真实姓名、驾驶证号、驾驶证有效期、驾龄 |
| 证件照片上传 | 上传驾驶证照片 picURL |
| 认证类型选择 | authType 选择 |
| 提交认证 | `SubmitDriverCert` |
| 查询认证状态 | `StatusDriverCert` |

### 2.7 钱包/收入页 (`wallet.html`)
**受益接口**: `DriverOrderHistory`（汇聚收入数据）

| 功能点 | 说明 |
|--------|------|
| 今日收入 | 汇总今日订单收入 |
| 本月收入 | 汇总本月订单收入 |
| 收入明细列表 | 按日期分组的收入记录 |
| 累计收入 | 历史总收入统计 |

## 四、技术方案

### 4.1 技术选型
- **纯静态 HTML/CSS/JS**，与现有 user-web、admin-web 保持一致
- **移动端优先**，适配手机屏幕（max-width: 430px），参考 user-web 的样式风格
- **品牌色**: `--primary: #FF6B00`（与飞猪出行品牌一致）

### 4.2 文件结构
```
Online ride-hailing/
└── driver-web/
    ├── login.html          # 登录/注册页
    ├── index.html          # 首页/工作台
    ├── order-detail.html   # 订单详情页
    ├── order-history.html  # 历史订单页
    ├── profile.html        # 个人信息页
    ├── certification.html  # 认证中心
    ├── wallet.html         # 钱包/收入页
    ├── styles.css          # 公共样式（移动端花小猪风格）
    ├── api.js              # API 请求封装（gRPC-Web 或 HTTP 代理）
    └── app.js              # 公共逻辑（状态管理、路由跳转）
```

### 4.3 API 调用方式
由于后端是 gRPC 接口，前端需要通过以下方式之一调用：
- **方案 A**: 在 admin-api 或 user-api 中添加 HTTP 代理路由，将 REST 请求转发为 gRPC 调用
- **方案 B**: 使用 gRPC-Web 直接调用（需要后端支持）
- **推荐方案 A**，与现有架构一致

### 4.4 页面风格参考
- 采用 user-web 的移动端风格（花小猪橙色主题）
- CSS 变量体系保持一致
- 底部导航栏模式
- Toast 消息提示
- 卡片式布局

## 五、实现优先级

| 优先级 | 页面 | 理由 |
|--------|------|------|
| P0 | login.html | 入口页面，所有功能的前置条件 |
| P0 | index.html | 核心工作台，司机日常操作主页面 |
| P1 | order-detail.html | 订单操作核心流程 |
| P1 | order-history.html | 历史查询高频需求 |
| P2 | profile.html | 个人信息管理 |
| P2 | certification.html | 认证流程，注册后必需 |
| P3 | wallet.html | 收入查看，辅助功能 |
